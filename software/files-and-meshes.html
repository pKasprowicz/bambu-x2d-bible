File formats & mesh repair

Every 3D print starts with a file, and many failed prints start with a bad one. Learn which formats to use, what a healthy mesh looks like, how to find and fix problems, and how to find, license and archive models responsibly.

File formats compared

Formats fall into four families. Mesh formats (STL, OBJ, PLY, AMF, 3MF) store triangles. Solid (B-rep) formats (STEP, IGES, Parasolid) store exact surfaces, ideal for editing in CAD. Scene formats (glTF, OBJ with materials) store meshes plus textures for display. Instruction formats (G-code and its variants) store printer commands and are the output of the slicer, not the input. See Slicers compared for how a mesh becomes G-code.

The three-file habit

For each project keep: (1) the native CAD or script file, (2) a STEP export for portability, and (3) the 3MF project you actually sliced. STL is an acceptable throw-away export, not an archive.

G-code flavors and containers

Plain .gcode files are text and can be read in any editor. .bgcode is a compact binary G-code format designed to cut file size and speed uploads on printers that support it (introduced by Prusa for its firmware). Bambu Lab printers use .gcode.3mf: a 3MF package containing the plate's G-code, thumbnails and metadata, which is what Bambu Studio sends to the printer. These containers are described in G-code, firmware & ecosystem. Never edit a file you do not understand and never run G-code from an untrusted source on a printer you care about.

Mesh anatomy

A mesh is a surface described by three things: vertices (points in space), edges (lines between two vertices) and faces (usually triangles bounded by three edges). Each face has an outward-pointing normal, a direction perpendicular to the face that tells the software which side is "outside". A printable mesh must enclose a volume unambiguously.

Manifold and watertight, explained

A mesh is manifold when every edge is shared by exactly two faces, and the faces around each vertex form a single connected fan. It is watertight when it has no holes, so water poured inside could not leak. Slicers compute the interior by counting how many surfaces a ray crosses; if the surface has holes, overlaps or flipped faces, the count goes wrong, and the slicer may print nothing, fill the wrong region or produce odd gaps.

Resolution, tessellation and faceted curves

A mesh made of flat triangles can only approximate a curve. When CAD exports a cylinder to STL, it chooses how many segments to use, controlled by two numbers: the chord (linear) deviation, the largest distance between the true curve and the triangle edge, and the angular deviation, the maximum angle between neighboring normals. Coarse settings produce visible facets, even if your printer could do much better.

Why curves look faceted even at 0.1 mm layers

Layer height controls detail in Z; tessellation controls detail in X and Y. A beautifully smooth stack of layers still shows polygon corners if the STL was exported with a 0.1 mm chord deviation on a large cylinder. If the slicer is set to arc fitting, it can sometimes smooth small jaggedness, but it cannot recover detail missing from the mesh. Re-export with finer tolerance, or export 3MF/STEP.

🔧 A manual repair recipe in Blender
  1. Import the model and set the scene unit scale to millimeters (see scaling and units).
  2. Enable the 3D-Print Toolbox. Run Check All: it reports non-manifold edges, intersections, thin walls and overhangs.
  3. In Edit Mode, select non-manifold geometry (Select → Select All by Trait → Non Manifold). Delete loose geometry, merge by distance (a tiny threshold such as 0.0001 m), and fill holes (F or Fill Holes).
  4. Recalculate normals outside (Shift+N).
  5. If overlapping shells remain, use a Boolean modifier (Union, Exact) to merge them, then apply it.
  6. Re-run the check, export as 3MF or STL, and load the result into the slicer for a final preview.

Boolean pitfalls

Boolean operations (union, difference, intersection) on meshes rely on clean surfaces. Common failure causes: coplanar faces (two faces lying exactly on the same plane), tiny gaps or overlaps between parts, non-manifold input and extremely thin slivers. The results are often missing faces or flickering "z-fighting" surfaces.

Decimation, remeshing and hollowing

Decimation

Decimation reduces the number of triangles while trying to keep the shape. Scans and sculpts routinely have millions of triangles, which makes slicing slow and files huge. Target a deviation of 0.01–0.05 mm from the original, and keep flat areas flat; most tools allow you to preserve boundaries and sharp edges. Remeshing goes further: it rebuilds the surface with evenly sized triangles, often required before Boolean operations or smoothing. Both operations can blur sharp edges and small text, so compare the result to the original.

Hollowing

Hollowing removes the interior of a solid model to save material, mostly for resin printing; FDM printers already print the interior as sparse infill, so hollowing is rarely useful for FDM unless you want an empty cavity (for example a lightweight shell or to insert weights or electronics). If you hollow, leave a wall of at least 2 mm, add drain or escape holes for resin, and verify the inner surface is also watertight.

Splitting and cutting with connectors

A model too large for the plate, or one with difficult overhangs, can be cut into parts that print flat and are joined afterwards. Good cuts follow natural seams (a collar, a sleeve edge), put flat faces on the plate and keep joints away from highly loaded areas. Slicers such as Bambu Studio and OrcaSlicer include a cut tool with connectors (pegs, dovetails) that create matching pins and sockets with adjustable clearance, so the parts self-align when glued.

Scaling and units mistakes

STL files carry no units. Slicers assume millimeters, while some CAD or game programs export inches, centimeters or meters. The result is a model that is the wrong size by a predictable factor.

After import, check the object's dimensions in the slicer's object panel against a feature you know (a bolt hole, the overall height). Scaling the whole object also scales hole diameters and tolerances, so for functional parts correct the source file instead of enlarging in the slicer.

Model repositories and licensing

You rarely need to start from a blank screen. The main sources, each with its own audience and terms:

Printables

Run by Prusa Research; strong community, many functional designs, with contests and a clear license badge on each model.

MakerWorld

Run by Bambu Lab; integrated with Bambu Studio and Handy, with printer-specific profiles uploaded by authors and a points/rewards system.

Thingiverse

One of the oldest repositories (UltiMaker); huge archive, uneven quality and sometimes dated files.

Thangs

Geometric search across many sources plus its own hosting and a community.

Cults

Marketplace oriented toward designers, with a mix of free and paid models.

GrabCAD

Engineering-oriented library of CAD files, often in native or STEP format.

Careful and general, not legal advice

Creative Commons licenses apply to the design file; they do not clear trademarks, characters or patents embedded in it. A "free" model of a copyrighted character may be an infringing upload. Whether a physical print counts as a derivative or a commercial use can depend on the exact license text and jurisdiction. If you intend to sell, read the license, the site's terms and, where it matters, ask the author in writing. See Economics, licensing & sustainability.

Checking printability

Analysis tools color-code the model so problems are visible before you print. Use them as a second set of eyes in addition to the slicer's layer preview.

Archiving and version control

Models are binary files that grow quickly, and plain Git stores every version in full. Git LFS (Large File Storage) keeps lightweight pointers in the repository and the large files on a separate server, which keeps cloning fast. Use Git for text sources (OpenSCAD, CadQuery, notes) and LFS for .3mf, .stl, .step.

# one-time setup in a repository
git lfs install
git lfs track "*.3mf" "*.stl" "*.step" "*.blend"
git add .gitattributes
git commit -m "Track model files with Git LFS"

Naming conventions

  • Use lowercase, hyphens or underscores, and no spaces: phone-stand_v3.3mf.
  • Put the part, revision and variant in the name: bracket_40x30_t4_r2.step.
  • Add the printer or material only to sliced projects: bracket_r2_x2d_petg.3mf.
  • Never overwrite a printed version; bump the revision so you can reproduce what you printed.
  • Keep the date format ISO (2025-03-14) when you need dates, so names sort correctly.

Metadata worth keeping

A short README.md or notes file beside each project pays off months later. Record: the purpose and source URL (and license) of any remix, the units and key dimensions, the printer and nozzle, the filament brand and temperatures that worked, settings that were changed from default and why, print time and weight, and a photo of the result. 3MF files also carry metadata fields (title, designer, license) that repositories can read; fill them in when you publish.

Troubleshooting file problems

Most "the slicer is doing something strange" reports trace back to the file, not the printer. Work through the symptoms below before changing print settings.

Pre-slice checklist

  • The file opens at the expected size, in the expected units.
  • The slicer reports no errors, or the auto-repair result looks right in the preview.
  • The smallest feature is at least one line width thick; ideally at least two for strength.
  • The orientation puts the flattest, largest face on the bed, or follows the load direction (see strength and orientation).
  • Overhangs beyond about 45–60° are supported or redesigned (see supports, bridges and overhangs).
  • The source file and the exported file are named consistently with a version number.

Round-trip rule

If you need to change a part later, the file you keep must be the one you can edit: a native CAD file, a parametric script, or at least a STEP. STL and 3MF are what you send to the printer, not what you design in.

Meshes from scans and sculpts

Photogrammetry, structured-light and handheld 3D scanners produce dense, noisy meshes that often have holes where the scanner could not see (undercuts, shiny or dark surfaces). Sculpting tools produce high-polygon models with organic shapes but no real wall thickness. Both need cleanup before printing: fill holes, remove floating fragments, smooth noise, decimate to a manageable size, and give the object real thickness (offset or solidify the surface, or hollow it). Treat the cleanup as a small project in itself, and compare the result against the original object with calipers to be sure that dimensions were not altered by smoothing.

What the slicer does on import

A slicer reads the mesh, merges coincident vertices, checks for open edges, may apply automatic repair, and slices it into layers by intersecting the surface with horizontal planes. This explains several behaviors: tiny gaps smaller than the slicing resolution are closed, overlapping shells are merged or treated as a union, and extremely thin walls are either widened or dropped depending on the wall generator. A model that previews well and has a sound closed surface almost always slices well; if previews show odd gaps, the answer is in the mesh, not in the print profile. Details about each setting are in slicer settings.

Quick self-check

Which format is best as a long-term master file of an engineered part?

  • STL
  • The native CAD file plus a STEP export
  • G-code

STEP preserves exact geometry; STL and G-code are lossy or machine-specific outputs.

A model appears solid in a viewer but vanishes in the slicer. A likely cause?

  • Layer height too low
  • Inverted normals or an open shell
  • Too many walls

Slicers use normals and closed surfaces to decide what is inside; errors can make the part vanish.

Your Boolean subtract leaves a thin skin over the hole. How do you fix it?

  • Increase infill
  • Extend the cutter beyond the surface so no faces coincide
  • Export as OBJ

Coincident faces confuse Boolean algorithms; overshoot the cutter.

Key takeaways

  • Use 3MF for slicing and sharing, STEP for exact geometry, and treat STL as a throw-away export.
  • A printable mesh is closed, manifold, has outward normals and walls thicker than a line width.
  • Faceted curves come from coarse tessellation, not from the printer; re-export with finer tolerance.
  • Repair in escalating steps: slicer, mesh tool, then rebuild the source.
  • Check the license before you remix or sell, and record where each file came from.
  • Keep text sources in Git and binaries in Git LFS, and name files with versions.
